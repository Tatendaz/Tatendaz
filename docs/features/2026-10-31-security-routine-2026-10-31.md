# Security sweep 2026-10-31: follow-redirects

**Branch:** security/routine-2026-10-31
**Date:** 2026-10-31

## Summary
Moves `follow-redirects` from 1.16.1 to 1.16.2 in `scripts/statsenv/package-lock.json`.

## Motivation
GHSA-mrwp-f3q8-3g9p (high, published 2026-10-30). In 1.16.0 and 1.16.1, a
`sensitiveHeaders` array from another realm is dropped, so custom credential headers can
follow a redirect to another host. It is in the lockfile as a dependency of `axios`.
`scripts/render_pin.mjs` gets its data from `gh api` and makes no HTTP request through
`axios`, so the vulnerable path is likely not reached. The bump keeps the lockfile clean.

## What changed
- `scripts/statsenv/package-lock.json`: the `follow-redirects` entry only.

## Notes
- 1.16.2 was published 2026-10-25, inside the 7-day cooldown. The advisory names it as the
  only fixed version. Same publisher as 1.16.1 (rubenverborgh), no install scripts, and the
  code diff is one line (`Array.isArray` instead of `instanceof Array`).
